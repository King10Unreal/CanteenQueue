# Canteen Queue Management

A Render-ready web application for campus food ordering and live queue management. It implements the roles in the supplied use-case diagram with server-side authorization.

## Roles

| Role | Access |
| --- | --- |
| Student | Create a student account, browse available food, place a demo-paid order, and view their own live token and queue position. |
| Staff | Log in with a staff ID, see active orders, progress each order from queued to preparing to ready to collected, and update menu availability through the protected API. |
| Admin | Log in with an admin ID, use all staff capabilities, create staff accounts, and view aggregate operational counts. |

The server is the authority for every role. Hiding UI is only a convenience; each protected API route checks the signed-in role.

## Run locally

```bash
npm install
npm start
```

Open `http://localhost:3000`.

## Deploy on Render

1. In Render, select **New > Blueprint** and connect this GitHub repository.
2. Render detects `render.yaml`; review it and choose **Deploy Blueprint**.
3. Render creates a Node web service, installs dependencies with `npm ci`, starts `npm start`, and checks `/api/health`.
4. Open the generated `onrender.com` address once the deploy is live.

`SESSION_SECRET` is generated by Render. For a real deployment, replace the JSON demo store with a managed database before relying on registrations or orders: the local Render filesystem is not durable across redeploys or restarts. The current setup is appropriate for a project demonstration.

## Security notes

Passwords are salted and hashed with Node's `scrypt`. Session cookies are `HttpOnly` and `SameSite=Lax`; they become `Secure` under `NODE_ENV=production`. This project intentionally marks ordering as `demo-paid`; it does not collect or process real payments.
